# 智能对象的纯矢量叠加修复

2026-10-14，社区构建 `2.1.0-preview.9`。

用户发现部分矢量智能对象导入后，仍通过缓存位图的透明度蒙版显示叠加颜色。此前仅按 `vector-smart-object` 节点类型判断是否完成矢量导入是不充分的。

## 原因与改动

该 PSD 的 75 个 SVG 智能对象实例中，69 个有图层样式叠加：60 个纯色、9 个线性渐变。解析器已读取原始 SVG 路径，但旧的通用叠加逻辑为它们调用 `imageLayer`，再生成“缓存图片蒙版 + 叠加矩形”。

本次对完全不透明、正常混合的叠加使用原始矢量几何：在 Figma 导入 SVG 后，直接替换实际路径的填充和描边，不创建缓存图片蒙版、叠加矩形或重复轮廓。保留原始路径、空心区域、描边宽度和源透明度。最上方完全不透明叠加覆盖其他叠加的颜色，按同一原始透明度重着色。

渐变以 PSD 图层效果的参考坐标为基准，通过画板/父组变换及实际路径变换映射到每个子路径。不同子路径共享同一渐变，不按各自包围盒重新开始渐变。画板重新定位时同步效果参考坐标。

外观对照还发现 3 个 Illustrator SVG 的图形画在声明的 viewBox 外，缓存蒙版曾掩盖其位置问题。修复会计算实际路径和描边范围，仅在 PSD 保存的智能对象尺寸与绘图区尺寸吻合时调整 viewBox，保留有效 SVG 原有留白。曲线标准化使用固定版本的 [svgpath 2.6.0](https://github.com/fontello/svgpath)，MIT 许可正文已随包保留。

对尚不支持的半透明/特殊混合、内嵌图片、滤镜和复杂源渐变，保留明确标记的缓存回退。不会将这类回退报告为纯矢量。实际节点统计也检查填充与描边中的 IMAGE 画笔，避免把带图片的矢量容器当作真实矢量。

## 验证标准

同时检查场景解析结果和实际创建树，不能只检查节点名称或 `VECTOR` 类型：

- 75 个矢量智能对象实例均有实际路径。
- 其完整子树内无图片填充、无位图蒙版；该样本子树内没有任何蒙版。
- 69 个叠加效果有直接填充标记，能够编辑路径及路径画笔。
- 真实 PSD 编解码验证颜色和渐变效果不创建图片资源。
- 数值验证多个子路径在旋转、缩放、倾斜及画板偏移后，同一个文档坐标得到一致的渐变坐标。
- 验证透明度、描边和路径数据保持正常，以及复杂效果的明确回退。

| 该 PSD 的导入结果 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 矢量智能对象的缓存叠加蒙版 | 69 | 0 |
| 文档图片节点 | 95 | 26 |
| 文档蒙版节点 | 85 | 16 |
| 原生可编辑文字 | 148 | 148 |

剩余 26 个图片节点和 16 个蒙版属于文档其他内容，不属于这 75 个矢量智能对象。该样本另有 8 个内外发光兼容问题，本次没有将其算作已修复。

源码回归与最终 `code.js` / `ui.html` 浏览器回归使用严格节点测试环境，不是 Figma 渲染器。渐变位置和最终视觉仍需在真实 Figma 核对。本次未改写原 PSD，未重新发布社区插件。

## 使用

直接在 Figma 开发插件入口加载 `D:\WB\导入figma插件\community\manifest.json`，关闭旧插件窗口，重新运行 FigImport 后再次导入原 PSD。当前版本为 `2.1.0-preview.9`。
